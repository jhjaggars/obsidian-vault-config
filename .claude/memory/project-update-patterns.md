# Project Update Patterns

## Meeting-Derived Deadline Callouts

**When it applies:** Creating or updating a project status document for a JIRA Outcome (or any project) that has an associated recurring review meeting.

**What to do:** Find the next occurrence of the review meeting and add a `[!calendar]` callout near the top of the update doc (after the JIRA link, before the main content) with:
1. A wiki-link to the meeting note
2. The meeting date in human-readable format
3. A Dataview inline countdown formula

**How to find the next meeting:**
- Check the project note's **Related Items** section (auto-generated by `/project-sync`) for linked meeting notes
- Look in `Meetings/` for upcoming instances of the recurring meeting by name
- Check synced Calendar data in `Drive/calendar/` if available

**Callout format:**

```markdown
> [!calendar] Next <Meeting Series Name>
> [[Meetings/YYYY/MM-Month/DD-Day/Meeting-Title|Display Name]] — <Day Mon DD, YYYY HH:MM AM/PM TZ>
> ⏳ `= date("YYYY-MM-DD") - date(today)` remaining
```

**Real example** (from `docs/2026-02-23-HCMSTRAT-15-Update.md`):

```markdown
> [!calendar] Next Outcome Refinement
> [[Meetings/2026/03-March/09-Monday/Bi-weekly-HCM-Outcome-Refinement|Bi-weekly HCM Outcome Refinement]] — Mon Mar 9, 2026 11:05 AM EDT
> ⏳ `= date("2026-03-09") - date(today)` remaining
```

**Generalization:** This applies to any project update where a recurring meeting serves as a natural checkpoint — not just HCMSTRAT-15. Whenever writing a project status doc, proactively look for the next relevant review meeting and include the callout.
