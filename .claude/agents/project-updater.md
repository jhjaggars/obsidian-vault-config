# Project Updater Agent

Discovers active projects and updates their Related Items sections with matched vault data.

**You MUST use the ReplaceSection or Edit tool to write your results.** Do not just report findings — write them into the project files.

---

## Wiki-Linking Convention

- **People names:** `[[Name]]` if `People/<Name>.md` exists; `[[Page Name|Display Name]]` for aliases; unresolved `[[Name]]` is acceptable.
- **JIRA keys:** `[[jira/KEY|KEY]]` if `jira/<KEY>.md` exists, otherwise `[[KEY]]`.
- **Projects/software:** Wrap known projects in `[[wiki-links]]` (e.g., `[[ROSA]]`, `[[RHOBS]]`).
- **Pipe escaping in tables:** Inside table cells, escape as `[[jira/KEY\|KEY]]`.

CORRECT callout format: `> [!info]` (single bracket). INCORRECT: `> [[!info]` (wiki-link syntax, never use).

---

## Step 1: Discover Active Projects

### 1a. Parse Work Pipeline

Read `Work Pipeline.md`. Extract wiki-link items from `## Ideas`, `## Early`, `## Mature`.
Skip `## Complete`. Items look like `- [ ] [[Project Name]]`. Skip plain-text items without wiki-links.
Record which column each project belongs to (Ideas / Early / Mature).

### 1b. Parse Personal Pipeline

Read `Personal Pipeline.md`. Extract wiki-link items from `## Ideas`, `## Active`, `## On Hold`.
Skip `## Done`. Handle aliased links like `[[spacev3|Space V3]]`.

### 1c. Resolve Project File Paths

For each wiki-link, resolve to a file:
1. Try `Projects/Work/<name>.md` or `Projects/Personal/<name>.md`
2. Glob `Projects/**/<name>.md` — **exclude** `Projects/Work/Archived/`
3. Try `Areas/<name>.md`
4. If not found, warn and skip

---

## Step 2: Update Project Notes

For each resolved project:

### 2a. Extract Match Criteria

**Prefer frontmatter:** Read YAML frontmatter (first 15 lines). If `jira_keys` and `keywords` fields exist, use those directly.

**Fallback:** Scan for JIRA key patterns (`[A-Z]+-\d+`) and derive 2-4 keywords from the title and content.

### 2b. Process @claude Directives

Scan for unprocessed `@claude, <instruction>` lines (skip lines starting with `@claude (done` or `@claude (skipped`).

For each (up to 5 per note):
1. Execute the instruction using Edit tool within the directive's `##` section
2. Mark done: `@claude (done YYYY-MM-DD), <instruction>`
3. On failure: `@claude (skipped YYYY-MM-DD: <reason>), <instruction>`

Safety: Do NOT delete entire sections, modify `## Related Items`, or edit other files.

### 2c. Match Against Vault Data

Search these sources for JIRA keys and keywords:

- **JIRA** (`jira/*.md`): Match by key in filename or keyword in `summary` frontmatter
- **PRs** (`prs/*.md`): Match by keyword in `title` frontmatter
- **Drive** (`Drive/*.md`): Top-level only, match filename or first 30 lines. Skip subdirectories.
- **Meetings** (last 14 days): Match on filename only
- **Slack** via sqlite3: `sqlite3 ~/.config/pkm-sync/slack.db "SELECT channel_name, author, content, created_at FROM slack_messages WHERE content LIKE '%keyword%' AND created_at >= date('now', '-14 days') ORDER BY created_at DESC LIMIT 5"`
- **Gmail** via pkm-sync: `pkm-sync search "<keyword>" --limit 5 --format json`

Skip Slack/Gmail gracefully if unavailable.

### 2d. Extract Deadlines

Gather deadlines for use by the daily-summarizer agent:
- From project note: `## Timeline` tables, `## Next Steps` dated items, frontmatter `deadline`/`due`/`target_date`
- From linked JIRA: `jira issue view <KEY> --raw 2>/dev/null | python3 .claude/skills/daily-sync-all/scripts/jira_deadlines.py` (Early/Mature only)

### 2e. Write Related Items Section

**You MUST use ReplaceSection to write this section.** Do not just report the matches.

```
ReplaceSection(file_path, "related-items", content)
```

Content format:
```markdown
## Related Items

> [!info] Auto-generated by project-updater on YYYY-MM-DD. Do not edit manually.

### JIRA Issues
| Key | Summary | Status |
|-----|---------|--------|
| [[jira/KEY\|KEY]] | Summary... | Status |

### Pull Requests
| PR | Title | Status |
|----|-------|--------|
| [[prs/repo-123\|repo#123]] | Title... | Open |
```

Omit subsections with zero matches. If a note lacks section markers, fall back to Edit. **NEVER modify content outside `## Related Items`** (except for @claude directives).

---

## Step 3: Report Summary

Output a brief summary: projects processed, match counts, directives executed, errors.
